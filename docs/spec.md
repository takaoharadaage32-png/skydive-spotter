# Skydive Spotter 仕様書

2026-10-17 時点

## 1. 概要

open-meteoの上空風予報から、ジャンプランのExit地点（グリーンライト点）を計算するWebツール「Skydive Spotter」を作る。計算はUSPA簡易方式（Level 1）と層別計算（Level 2）の2方式を並べて表示する。

- **目的**：Exit高度・オープン高度・オープン位置・ジャンプラン方向を入力し、Exit地点・ドリフト量・グループ間隔を出す
- **利用者**：ジャンプマスター、スポットを学ぶ学生、パイロット
- **方式**：スマホで使えるWebアプリ（PWA）。非商用で公開する（open-meteo無料APIの条件）
- **安全上の位置づけ**：計算は予報に基づく推定値。最終判断は機上の目視（SPACE）とDZのルールに従う旨を画面に常時表示する

**対象外（初版）**：ムーブメント／ウイングスーツの飛行経路、物理シミュレーション（Level 3）、商用利用。

## 2. 用語・座標系・単位

内部計算はすべてSI単位（m, s, m/s）、原点はターゲット（着地点）とし、表示のときだけft・kt・マイルに変換する。

| 用語 | 定義 |
| --- | --- |
| ターゲット | 着地目標点。座標の原点 (0, 0) |
| 座標 | x＝東(+)、y＝北(+)、単位m。地図表示時に緯度経度へ変換 |
| AGL / MSL | 地上高 / 海抜高。計算はすべてAGL |
| 風向 | 吹いてくる方向（気象の慣例）。0°＝北から吹く |
| ドリフトベクトル (u, v) | 風で流される向きのベクトル。風向 θ・風速 V のとき u = −V·sin θ、v = −V·cos θ |
| ジャンプラン方向 | 機体の進行方位（表示・入力は磁方位、内部は真方位） |
| オープン位置 | キャノピーを開く地点（ターゲットからの方位・距離） |
| Exit地点 | 機体から出る地点。ジャンプラン上のグリーンライト点 |
| Forward throw | Exit直後に機速で前へ進む距離 |

単位換算の定数：1 ft = 0.3048 m、1 kt = 0.514444 m/s、1 mph = 0.44704 m/s、1 マイル = 1609.344 m。方位の計算は内部ではすべて真北基準で行い、表示は磁方位にする（2.1）。

### 2.1 表示単位と方位（決定事項）

単位は画面上で切り替えられ、左側が初期値。

| 対象 | 初期値 | 切替 |
| --- | --- | --- |
| 高度 | ft | m |
| 距離 | m | マイル |
| 風速 | kt | m/s |
| 方位 | 磁方位（例 278°M） | ― |

- 画面に出す方位（ジャンプラン、Exit地点・オープン位置の方位、ドリフト方向、風向）はすべて磁方位で表示し、末尾に「M」を付ける
- 入力するジャンプラン方向・オープン位置の方位も磁方位で受け取り、内部で真方位に変換する
- 偏角はターゲットの緯度経度と日付から世界磁気モデル（WMM）で計算する。設定で手動上書きできる
- 換算：磁方位 = 真方位 − 偏角（東偏を正）。日本は西偏なので、磁方位は真方位より数値が大きくなる
- open-meteoの風向は真方位なので、取得後に磁方位へ変換して表示する

## 3. 入力項目

必須は上の4項目（ユーザー指定）と DZ情報。それ以外は初期値を持ち、設定画面で変更できる。

| 項目 | 単位（表示） | 初期値 | 必須 | 備考 |
| --- | --- | --- | --- | --- |
| Exit高度 | ft AGL | 13,000 | ○ | 3,000〜18,000 の範囲チェック |
| オープン高度 | ft AGL | 3,000 | ○ | Exit高度より低いこと |
| オープン位置 | 方位°・距離m | 自動提案 | ○ | 未入力時は「キャノピードリフトの逆方向」を提案（6章） |
| ジャンプラン方向 | 度（磁方位） | 自動提案 | ○ | 未入力時はExit高度の風上方向を提案 |
| ターゲット緯度・経度 | 度 | ― | ○ | 地図タップでも指定可 |
| DZ標高 | m MSL | open-meteoのelevation | ○ | 手動上書き可 |
| ジャンプ予定時刻 | 日時 | 次の正時 | | 風データの時刻選択に使う |
| 種目（落下モデル） | 選択 | ベリー | | ベリー / フリーフライ / 学生AFF / タンデム（5章） |
| キャノピー降下率 | ft/分 | 1,000 | | USPA ISP の標準値 |
| 機体ジャンプラン対気速度 | kt | 85 | | 機種プリセットあり |
| グループ構成 | 人数・種目の配列 | 1組 | | セパレーション計算用 |
| 風データ補正 | 層ごとの風向・風速 | なし | | 手入力で予報を上書き（予備手段） |

入力値はブラウザに保存し（DZ・機体プリセット）、次回起動時に復元する。

## 4. 風データ取得と風テーブル

open-meteo Forecast API（キー不要、非商用無料）から気圧面の風と地上付近の風を取り、1,000ftごとのAGL風テーブルに変換する。日本の地点では自動選択でJMA MSMが使われる。

### 4.1 リクエスト

```
GET https://api.open-meteo.com/v1/forecast
  latitude, longitude        ターゲット座標
  hourly = wind_speed_10m, wind_direction_10m,
           wind_speed_80m, wind_direction_80m,
           wind_speed_120m, wind_direction_120m,
           wind_speed_180m, wind_direction_180m,
           wind_speed_{P}hPa, wind_direction_{P}hPa, geopotential_height_{P}hPa
           （P = 1000, 975, 950, 925, 900, 850, 800, 700, 600, 500）
  wind_speed_unit = ms
  timezone = auto
  forecast_days = 2
```

- 500hPa（約5.6km）までを取り、Exit高度18,000ftまでを確実に覆う
- 帰属表示「Weather data by Open-Meteo.com」（CC-BY 4.0）を画面に出す
- 利用上限：1日10,000回・1時間5,000回・1分600回。同じ地点・時刻は15分キャッシュする
- 失敗時はエラー表示し、手入力モード（3章の風データ補正）へ切り替えられるようにする

### 4.2 風テーブルの生成手順

1. ジャンプ予定時刻に最も近い時刻のデータを選ぶ（前後2時刻の補間はオプション）
2. 気圧面ごとに AGL高度 = `geopotential_height` − DZ標高 を計算し、AGLが負（地中）の面は捨てる
3. 地上付近の4点（10, 80, 120, 180 m AGL）を加え、高度順に並べる
4. 各点の風を (u, v) に分解する（2章の式）
5. 0ftからExit高度まで1,000ftごとに、u・vをそれぞれ高度で線形補間する。最上点より上は外挿しない（Exit高度が範囲外ならエラー）
6. 補間後の (u, v) から表示用の風向・風速を逆算する

風向を直接補間しない理由：359°と1°を平均すると180°になってしまうため。

### 4.3 データ構造

```ts
interface WindLayer {
  altAglFt: number;   // 0, 1000, 2000, …
  u: number;          // 流される向き 東成分 m/s
  v: number;          // 流される向き 北成分 m/s
  dirDeg: number;     // 表示用：吹いてくる方向（真方位。表示時に磁方位へ変換）
  speedKt: number;    // 表示用
  source: 'forecast' | 'manual';
}
interface WindProfile {
  validTime: string;  // ISO8601
  model: string;      // 例 "jma_msm"（取得できる範囲で）
  dzElevationM: number;
  layers: WindLayer[];
}
```

## 5. 落下モデル

落下は「加速区間＋一定速度」の2段で近似し、Level 1 と Level 2 で同じモデルを使う。両方式の差が風の扱いだけになるようにするため。

| 種目 | 終端速度 | 加速区間 | 備考 |
| --- | --- | --- | --- |
| ベリー（FS） | 120 mph（53.6 m/s） | 10秒で1,000 ft | 初期値 |
| フリーフライ | 160 mph（71.5 m/s） | 10秒で1,000 ft | 設定で変更可 |
| 学生AFF | 120 mph | 10秒で1,000 ft | ベリーと同じ |
| タンデム（ドローグ） | 120 mph | 10秒で1,000 ft | ドローグ展開後 |

- 数値は暫定値。実装前に USPA SIM 6-3（Freefall Time Table）と照合して確定する
- 空気密度による高度補正（上空ほど速い）は初版では行わない（Level 3 の範囲）
- 加速区間中は平均速度（1,000 ft ÷ 10 s）で落ちるとみなす

キャノピー降下は一定の降下率（初期値 1,000 ft/分 ≈ 5.08 m/s）とし、キャノピーの前進（滑空）は初版では考えない。オープンからキャノピーが飛び始めるまでの高度損失（約500 ft）も無視する。

```ts
interface FallModel {
  name: string;
  terminalMs: number;     // 終端速度 m/s
  accelTimeS: number;     // 10
  accelDropFt: number;    // 1000
}
// 高度 h1→h2（AGL, ft）の落下に要する時間を返す
function timeBetween(m: FallModel, exitFt: number, h1: number, h2: number): number
```

## 6. 計算ロジック

Exit地点はターゲットから逆算する：オープン位置 → フリーフォールドリフトを引く → Forward throw を引く。Level 1 と Level 2 は「ドリフトの求め方」だけが違い、それ以外の手順は共通。

### 6.1 計算の流れ（共通）

1. 風テーブル（4章）と落下モデル（5章）を用意する
2. キャノピードリフト D_canopy を計算する（Level 1 / 2）
3. オープン位置 P_open を決める。未入力なら P_open = −D_canopy（キャノピーで流される分だけ風上に置く）
4. フリーフォールドリフト D_ff を計算する（Level 1 / 2）
5. Forward throw T を計算する（6.4）
6. Exit地点 P_exit = P_open − D_ff − T
7. グループ間隔とExitウィンドウを計算する（6.5）

### 6.2 Level 1：USPA簡易方式

フリーフォール：Exit高度からオープン高度までの層の (u, v) をベクトル平均し、フリーフォール時間をかける。

```
D_ff = 平均風[h_open, h_exit] × t_ff
```

キャノピー：オープン高度から地上までの層を平均し、降下時間（オープン高度 ÷ 降下率）をかける。

```
D_canopy = 平均風[0, h_open] × (h_open / r_canopy)
```

平均範囲（決定）：Level 1 のフリーフォールは「Exit高度〜オープン高度」の層を平均する。USPA ISP の「Exit〜3,000 ft」は、オープン高度3,000 ftのときにこれと一致する。

### 6.3 Level 2：層別計算

1,000 ft ごとの各層 i について、その層にいる時間 Δt_i を落下モデルから求め、層の風をかけて足し合わせる。層の境界にExit高度やオープン高度がかかる場合は、その層を按分する。

```
D_ff     = Σ_i  w_i × Δt_i      （Δt_i = timeBetween(層iの上端, 層iの下端)）
D_canopy = Σ_j  w_j × Δh_j / r_canopy
```

層の風 w_i は層の上端と下端の (u, v) の平均とする。

### 6.4 Forward throw

無風時 0.2 マイル（約322 m）をジャンプラン方向に取り、対気速度に対する対地速度の比で縮める（暫定モデル）。

```
T  = 322 m × (GS / TAS) × r̂
GS = TAS + w_exit · r̂
```

r̂ はジャンプラン方向の単位ベクトル、TAS は機体対気速度、w_exit はExit高度の層の (u, v)。

### 6.5 グループ間隔とExitウィンドウ

- 必要距離：ソロ 1,000 ft（305 m）、小グループ 1,500 ft（457 m）。大きいグループの加算量はDZ設定にする（USPAは「大きいほど加算」とのみ規定）
- 間隔（秒）= 必要距離 ÷ GS（GSは6.4の式）。秒単位で切り上げ
- Exit順は SIM 4-7 の標準順（ムーブメント1 → ベリー大→小 → フリーフライ大→小 → ムーブメント2 → AFF → タンデム → ハイプル → ウイングスーツ）で初期並べし、手動で変更できる
- **配置（決定）**：先頭グループを計算上のExit地点 P_exit に置き、後続グループは間隔×GS ずつジャンプランの進行方向へ並べる
- グリーンライト点 = P_exit（先頭グループ）、最終Exit点 = 最後のグループのExit地点

### 6.6 ジャンプラン方向の提案

未入力時は「Exit高度の風に正対する方向」（= Exit高度の風向）を提案する。上空の風が弱い（10 kt未満）ときは、地上風・地形に合わせて手動で決めるよう表示する。

### 6.7 警告条件

| 条件 | 表示 |
| --- | --- |
| Level 1 と Level 2 のExit地点の差が 200 m 超 | 風のシアが大きい日。Level 2 を優先 |
| GS が 40 kt 未満 | 上空の向かい風が強い。間隔を広げる |
| Exit高度が風データの範囲外 | 計算不可。手入力を促す |
| 予報時刻とジャンプ時刻が2時間以上ずれる | 予報の再取得を促す |

しきい値はすべて暫定値で、設定から変更できる。

## 7. 出力・画面

スマホ縦画面を基本に、3つのタブで構成する。機上では電波が届かないので、地上で取得した風と計算結果をそのまま表示できること。画面イメージは `docs/mockups/` を参照。

### 7.1 画面構成

| タブ | 内容 |
| --- | --- |
| 入力 | 3章の入力項目と表示単位の切替。DZ・機体プリセットの選択、「風を取得」ボタン、取得時刻とモデル名の表示 |
| 結果 | 地図＋数値。Level 1 / Level 2 の切替、警告（6.7）、グループごとのExit地点と間隔、パイロット向けの一文 |
| 風 | 1,000 ftごとの風テーブル（高度・風向（磁方位）・風速）。フリーフォール区間とキャノピー区間に分け、手入力で上書きできる |

### 7.2 地図表示

- ターゲット、オープン位置、Exit地点（Level 1 / Level 2 を色分け）、ジャンプラン直線、各グループのExit点
- 500 m ごとの距離リング、方位記号と偏角
- 各層の風を矢羽根で表示（任意）

背景地図は国土地理院の地理院タイルを使い、計算結果をその上に重ねる。リアルタイムで読み込んで表示する使い方は、出典を明示すれば申請不要。

| 項目 | 内容 |
| --- | --- |
| 地図の種類 | 「地図」（標準地図）／「航空写真」（シームレス空中写真）／「なし」を切り替え |
| 出典表示 | 地図の隅に「出典：国土地理院（地理院タイル）」と一覧ページへのリンクを常時表示。重ねた線や点は本ツールで追加したものと明記する |
| オフライン | 地上で結果画面を開いたときに表示した範囲だけを端末に残す。広い範囲の一括ダウンロードはしない（利用規約の確認が済むまで） |
| Google Mapsで開く | Exit地点・オープン位置・ターゲットの座標を、Google Mapsアプリで開くリンクを付ける（APIキー不要） |
| 現在地 | 端末のGPSで現在地を表示（任意。地上での確認用） |

未確認事項：地理院タイルのキャッシュ・オフライン保存の可否は「国土地理院コンテンツ利用規約」本文で確認する。

### 7.3 数値出力

- Exit地点：ターゲットからの方位（磁方位）・距離（m / マイル）と緯度経度
- フリーフォールドリフト・キャノピードリフト（方位・距離）
- GS（kt）、グループ間隔（秒）、Exitウィンドウの長さ（m）
- パイロット向け：ジャンプラン方位と「グリーン：ターゲットから○°M・○マイル」「最終Exit：○°M・○マイル」の文。コピーボタン付き

### 7.4 常時表示

- 「計算は予報に基づく推定。最終判断は機上の目視とDZのルールに従う」
- 「Weather data by Open-Meteo.com」と地理院タイルの出典表示
- 方位が磁方位であることと、使っている偏角

## 8. 技術構成と実装手順

PWA（インストール可能なWebアプリ）として作り、計算部分はUIから切り離した純粋なTypeScriptにしてテストで固める。ネイティブ化が必要になったら、同じコードをCapacitorで包む。

### 8.1 技術スタック

| 用途 | 採用 |
| --- | --- |
| ビルド | Vite + TypeScript |
| UI | React |
| 地図 | Leaflet + 地理院タイル（標準地図・シームレス空中写真） |
| 偏角 | WMM（世界磁気モデル）の計算ライブラリ（npmで実績のあるものを選ぶ） |
| オフライン | vite-plugin-pwa（Service Worker）、風データと結果は IndexedDB に保存 |
| テスト | Vitest |
| 公開 | 静的ホスティング（GitHub Pages、HTTPS必須） |

### 8.2 ディレクトリ構成

```
src/
  core/            計算ロジック（UI・通信に依存しない）
    units.ts       単位換算
    vector.ts      風向⇔(u,v)、ベクトル演算
    magnetic.ts    真方位⇔磁方位（WMM）
    fallModel.ts   5章
    windProfile.ts 4.2 の補間
    spotLevel1.ts  6.2
    spotLevel2.ts  6.3
    spot.ts        6.1 の流れ・6.4〜6.7
  api/
    openMeteo.ts   4.1 のリクエストと変換
  ui/              画面（7章）
  storage/         プリセット・キャッシュ
tests/core/        core の単体テスト
```

### 8.3 テスト方針

- **無風**：ドリフト0、Exit地点 = オープン位置 − 322 m（ジャンプラン方向）
- **一様風**：全層同じ風なら Level 1 と Level 2 の結果が一致する
- **USPA例題**：毎分1/4マイルの風で3,000 ftから3分 → キャノピードリフト3/4マイル
- **風向の境界**：359°と1°の補間が0°付近になる
- **気圧面の地中除外**：DZ標高が1000hPaの高度より高い場合
- **磁方位**：偏角8°Wのとき真方位270° → 278°M、入力278°M → 内部270°
- **Exitウィンドウ**：先頭グループのExit地点が P_exit と一致する
- open-meteo の実レスポンスを1件保存し、変換のスナップショットテストに使う

### 8.4 実装順序

1. `core/` の単位換算・ベクトル・磁方位・落下モデル＋テスト
2. 風テーブル生成（手入力データで）＋テスト
3. Level 1 / Level 2 / Exit地点計算＋テスト
4. open-meteo 取得と変換
5. 入力・結果・風の画面（地図なし、数値のみ）
6. 地図表示（地理院タイル）
7. PWA化（オフライン、ホーム画面追加）
8. グループ間隔・警告
